How it scans

Five passes, one target.

Each stage runs against the same three inputs and feeds its own slice of the final risk score. Order matters — later stages depend on what earlier ones surface.

01 🌐

Subdomains

Enumerates exposed subdomains from certificate transparency logs and DNS records to map what's actually reachable.

INPUT · domain
02 🛡️

Security headers

Checks every discovered host for missing HSTS, CSP, X-Frame-Options and related response headers.

INPUT · subdomains
03 🔒

TLS / SSL

Flags expired certificates, weak cipher suites and outdated protocol versions across the exposed surface.

INPUT · subdomains
04 🔑

Leaked secrets

Pattern- and regex-matches public repos in the GitHub org for API keys, tokens and credentials left in history.

INPUT · GitHub org
05 ✉️

Breach exposure

Checks each team email against HaveIBeenPwned to see which accounts already appear in known breaches.

INPUT · emails
